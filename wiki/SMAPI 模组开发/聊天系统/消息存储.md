## 详细组件分析

### 消息数据结构设计
建议的消息实体字段包括：
- 消息 ID：全局唯一标识，建议使用单调递增或带会话前缀的 ID
- 时间戳：UTC 时间，用于排序、筛选、归档
- 发送者：会话内角色或 NPC/玩家标识
- 接收者：单个接收者或群组标识
- 内容：文本、富文本或结构化载荷
- 状态：待发送、已送达、已读、失败、归档等
- 元数据：扩展字段，如标签、分类、摘要、哈希校验值

#### 字段复杂度与约束
- 时间复杂度：插入 O(1)，按时间倒序遍历 O(n)，过滤 O(n)
- 空间复杂度：每条消息 O(m)，m 为内容长度
- 约束建议：
  - Id 唯一且稳定
  - Timestamp 严格递增
  - Content 非空且有长度上限
  - State 仅允许合法转换

### 内存缓存与会话组织
- 会话键：可用 “发送者+接收者” 或 “群聊ID” 作为键
- 内存结构：字典映射会话键到消息列表，便于快速查找
- 容量控制：保留最近 N 条热消息，其余下沉到持久化
- 冷热分层：热点会话常驻内存，冷会话按需加载

### 持久化与数据同步
推荐策略：
- 增量落盘：每次写操作追加一条记录
- 批量合并：周期性将增量合并成快照
- 幂等写入：基于消息 ID 去重
- 失败重试：指数退避 + 最大重试次数
- 损坏修复：校验和校验，必要时重建索引

```mermaid
flowchart TD
    W(["内存写入成功"]) --> Queue["入队持久化任务"]
    Queue --> Worker["持久化工作线程"]
    Worker --> Write["写入增量日志"]
    Write --> Checksum["计算校验/哈希"]
    Checksum --> Commit{"提交成功?"}
    Commit -->|是| Merge["定时合并/压缩"]
    Commit -->|否| Retry["重试/告警"]
    Merge --> Done(["完成"])
    Retry --> Done
```

### 未读消息管理
未读计数需满足：
- 新增消息：接收方未读计数 +1
- 打开会话：将该会话所有未读置为已读，计数归零
- 单条已读：对应消息标记已读，未读计数相应减少
- 并发安全：读与写不竞争，采用锁或队列串行化

```mermaid
flowchart TD
    NewMsg["收到新消息"] --> IncUnread["收件人未读+1"]
    OpenChat["打开会话"] --> MarkRead["标记会话全部已读"]
    MarkRead --> ResetUnread["重置会话未读计数"]
    SingleRead["标记单条已读"] --> DecUnread["未读计数-1"]
```

### 数据一致性保证
- 原子更新：消息写入与未读计数更新在同一逻辑事务中
- 幂等性：重复写入不会导致计数翻倍
- 回滚策略：持久化失败时保留内存一致性，延迟重试
- 版本控制：消息结构升级时兼容旧格式

## 性能考虑
- 内存优化
  - 限制热缓存消息数量，避免无限增长
  - 使用对象池复用消息对象（若语言特性允许）
  - 定期释放不可达会话引用
- I/O 优化
  - 批量写入与合并
  - 异步落盘，避免阻塞主线程
  - 合理分片，避免单文件过大
- 查询优化
  - 时间范围索引
  - 会话局部性优化（LRU 访问）
  - 分页查询，避免一次性加载全部历史

## 故障排查指南
常见问题与建议：
- 未读计数异常
  - 检查是否存在重复标记已读或并发写未读计数
  - 验证打开会话时的重置逻辑是否覆盖全部未读
- 持久化失败
  - 检查重试与回滚逻辑
  - 校验文件格式与校验和
- 内存持续增长
  - 确认热缓存阈值与清理策略生效
  - 检查是否有泄漏的会话引用
- 查询缓慢
  - 评估是否需要引入时间索引或分页
  - 检查是否一次性拉取过多历史
